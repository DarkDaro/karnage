# KARNAGE — техническая документация

Игра: `karnage.html` (один файл, Canvas 2D, без зависимостей). Концепт: `karnage-concept.md`.
Обновлено: 30.09.2026. Все правки в коде помечены комментариями с датой («08.09», «30.09»).

## Запуск
- Обычный браузер: открыть `karnage.html` двойным кликом (сохранения работают).
- Для тестов через ZCode in-app browser: `python -m http.server 8613` в этой папке → `http://localhost:8613/karnage.html`. Кэш обходить `?v=N`.

## Архитектура (ключевые точки)
- **Ростер**: массив `CH` (11 бойцов, id 0–10). У бойца: `spec`/`spec2`/`fat` — буквенные комбо (D↓ U↑ L← R→ P рука K нога), `gear` (тип головного убора), флаги `dress`/`longhair`/`cape`/`claws`.
- **Приёмы**: `fireSpec`/`fireSpec2` — switch по `d.id`; супер — `startSuper` (цепочка событий `supEv`); фаталити — `fatalStep` (скрипт по кадрам, отметки t=50/170/300; цвета стихий — карта `WC`).
- **Состояния бойца**: idle/walk/jump/crouch/block/atk/cast/super/dash/hit/down/getup/frozen/net/dizzy/win/fatal/victim.
- **Флаги боя**: `dodging` (рывок, полная неуязвимость — проверяется в resolveHit/updProjs/взрывах), `jbuf`/`abuf` (буферы прыжка/атаки, 8 кадров), `poison`+`poisonC` (яд зелёный / кровотечение красное от `bl:1` у снарядов), `pale` (бледный труп после жатвы Кармин).
- **Отрисовка**: `pose()` (углы суставов; интро-позы по `q===id`, победы `w0===id`, касты `ci{}`), `drawF()`, `drawGear()` (ВАЖНО: внутри нет переменной `skin` — только `d.skin`), `drawPort()` (бюст для HUD/выбора), `WM{}` (походка каждого бойца: [частота, ноги, руки, покачивание, наклон]).
- **Арены**: `AR` (10), погода в `ambient()`, звёзды/щебень/швы генерируются в `AR.forEach`.
- **HUD/UI**: `drawHUD` (градиентная панель, акценты `d.acc`), `drawSelect` (сетка `CH.length`, panel справа), `drawPause` (способности с комбинациями).

## Чек-лист: добавить нового бойца
1. `CH.push({...})` + строка `CH[N].spec2=...` (уникальные комбо внутри самого бойца).
2. `drawGear`: своя ветка головного убора (или переиспользовать существующую).
3. `fireSpec`/`fireSpec2`: `case N:` — снаряды/эффекты (дальнобойные суперы НЕ использовать `autoHit` — он бьёт только в радиусе 48px).
4. `startSuper`: ветка `else if(id===N)` (цепочка `E(кадр, fn)`).
5. `fatalStep`: ветка в t=50 (флаг эффекта), частицы в 50–160, финал в t=170, цвет в `WC`.
6. Позы: интро (`q===N`), победа (`w0===N`), каст (`ci`), походка (`WM[N]`).
7. `RANGED` (дальник/ближник для ИИ).
8. Счётчики уже динамические (CH.length): лестница аркады, зал славы, карусель меню, clamp выбора.

## Методика тестирования (ZCode in-app browser)
- События клавиатуры: `window.dispatchEvent(new KeyboardEvent('keydown',{code:'KeyJ'}))` — на document НЕ доходит.
- Боевые тесты напрямую: `newBattle(i1,new Ctrl(KM1),i2,new Ctrl(KM2),arena); battle.mode='2p'; battle.p1.ctrl.ai=false; battle.p2.ctrl.ai=false; battle.phase='fight'; battle.phaseT=200;` затем `P1.startSpec(P2)` и замеры `setInterval` по 120 мс (окна замера должны быть длиннее времени полёта снаряда — иначе ложные нули).
- Синтаксис после правок: `node -e "const s=require('fs').readFileSync('karnage.html','utf8');new Function(s.match(/<script>([\s\S]*)<\/script>/)[1])"` — ловит потерянные скобки.
- Глубина скобок при ошибках: построчный сканер (строки+комментарии), дисбаланс ищется печатью depth перед каждым `function ` — функция с depthBefore>0 значит сломано выше.

## Готовые паттерны персонажей
- Вега (id 12): `hom:1` на снаряде — самонаведение в updProjs со капом скорости 4.6 (без капа звёзды разгоняются и пролетают мимо); `f.marks[]` — метки бойца, рисуются в render отдельным циклом перед декелями; фантомный флаг `bow` — лук при касте; `gear:'halo'` — парящий нимб.
- Аямэ (id 11): `d.blade` — оружие в руке при atk/cast/dash (катана от `fa`, позиции переднего кулака); `d.dress` — юбка Кармин; `d.longhair`/`d.cape` — волосы/плащ; gear-ветки: mask/helm/hood/horn/visor/band/corona/tail.
- Телепорт-удар (Аямэ спец2): `this.x=clamp(foe.x+foe.face*30,...); smoke(); resolveHit(this,foe,6,{})` — работает на любой дистанции.
- Супер с переносом (Сахра/Аямэ): `E(10,()=>{me.x=clamp(me.foe.x-me.foe.face*26..); smoke()})` затем autoHit-серия.
- DoT-варианты: `pois:1` (зелёный яд) и `bl:1` (красное кровотечение) на shard; цвет тика — `f.poisonC`.

## Известные грабли (не повторять)
- Персонажно-специфичные блоки отрисовки оборачивать в флаг (`if(d.dress)`) СРАЗУ — однажды юбка рисовалась всем бойцам.
- Комментарий `//` вставленный в середину однострочного JS съедает хвост строки (включая `}`).
- В drawGear нет `skin` — только `d.skin`.
- `(cond?SFX.a():SFX.b)()` — двойной вызов; правильно `(cond?SFX.a:SFX.b)()`.
- Замена хвостов вида `;}})` легко теряет скобку (drawArena, AR.forEach) — считать скобки до правки.
- rAF в новой вкладке IAB стартует с задержкой (FRAME=0) — не баг.
- Боевые тесты после goto: ЖДАТЬ FRAME>60 перед прогоном — иначе все замеры нулевые.
- Вставка в метод с циклом (drawFx и т.п.): закрывающие `}}` в якоре — считать ДВАЖДЫ; один раз вставили if наружу функции (ReferenceError f на верхнем уровне ловится прогоном скрипта в vm-песочнице со стабами DOM).
- Быстрая проверка «скрипт грузится целиком»: vm.runInContext со Proxy-стабами (document=mk(), addEventListener=()=>{}, rAF=()=>{}) — даёт стек top-level throw без браузера.
- `python -m http.server 8613` умирает молча — если `ERR_CONNECTION_REFUSED`, просто перезапустить; для обычной игры сервер не нужен (открыть файл двойным кликом).
